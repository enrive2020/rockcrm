# RockCRM

CRM для музыкальных школ. Мультитенантный SaaS: одна установка обслуживает
много школ, каждая видит только свои данные.

PostgreSQL 17 · FastAPI · React + TypeScript

---

## Зачем

Существующие CRM для учебных центров делятся на две группы, и обе промахиваются
мимо музыкальной школы.

Универсальные (Битрикс24, amoCRM) умеют воронку и бронирование ресурсов,
но не знают, что такое абонемент: списание за занятие, заморозку на каникулы,
отработку пропуска и зарплату преподавателя там либо считают в Excel,
либо заказывают у интегратора. Платформы для онлайн-школ (Antitreningi
и подобные) умеют уроки и тесты, но у них нет ни расписания, ни кабинетов,
ни посещаемости — офлайн-центру они не подходят вовсе.

В итоге администратор музыкальной школы ведёт расписание в одном месте,
остатки абонементов в другом, а зарплату преподавателей в третьем — и сводит
это руками.

RockCRM закрывает именно эту работу. Отметка посещаемости — одно действие,
которое само двигает остаток абонемента, начисление преподавателю
и напоминание о продлении.

## Три решения, на которых всё держится

**Абонемент — журнал, а не счётчик.** Остаток занятий не хранится
изменяемым числом: есть журнал операций, остаток — их сумма. Спор
с родителем «куда делось занятие» разрешается открытием журнала,
ошибочная отметка гасится компенсирующей записью, а не правкой задним числом.

**Правила копируются в абонемент при продаже.** Если школа завтра решит,
что прогул больше не сгорает, вчерашние абонементы не пересчитаются:
проданный абонемент — договор на условиях, действовавших при покупке.

**Двойную бронь запрещает база, а не код.** Ограничения исключения
по кабинету и преподавателю: два администратора, сохраняющие занятие
одновременно, оба увидели бы свободный слот, и проверка в приложении
здесь бесполезна.

## Разработка

```bash
docker run -d --name rockcrm-pg \
  -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=rockcrm \
  -p 5432:5432 postgres:17-alpine

for f in db/00*.sql; do psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f "$f"; done
```

Схеме нужно расширение `btree_gist` — оно есть в официальном образе
`postgres`, но отсутствует в урезанных сборках. Подробности
и порядок подключения приложения — в [db/README.md](db/README.md).
