# 19. Техническая архитектура MVP: QR-меню, интеграции POS, боты, голосовой ИИ, RAG, админка

*Дата: 30.10.2026. Цифры с пометкой **(оценка)** являются экспертными допущениями, а не данными источников.*

## 1. Итоговая архитектура (кратко)

```
Гость ──QR──> PWA-меню (Next.js/Nuxt, SSR + CDN РФ)
                 │
Telegram / VK / MAX боты ──┐
Телефон (Mango/Zadarma SIP)─┤──> Core API (NestJS или FastAPI, монолит-модули)
                            │        ├─ PostgreSQL 16 (+ pgvector для RAG)
                            │        ├─ Redis (кэш меню, очереди BullMQ/Celery)
                            │        ├─ S3-хранилище (фото блюд)
                            │        └─ Интеграционный слой: iiko Cloud / r_keeper / Poster
                            └──> AI-слой: LLM (YandexGPT / GigaChat; опционально зарубежные через прокси, с оговорками по 152-ФЗ)
                                          ASR/TTS: Yandex SpeechKit (основной), SaluteSpeech (резерв)
Админка (React + shadcn / Refine) ──> тот же Core API
```

Принцип: **один мультиарендный (multi-tenant) монолит** с изоляцией по `venue_id`, а не микросервисы. Для MVP команды 2-3 человек это быстрее в 2-3 раза **(оценка)**.

## 2. QR-меню

- **Фронт:** Next.js (SSR/ISR): быстрое первое открытие на 4G, SEO для страниц заведений. Альтернатива: Nuxt 3. Вес первой загрузки не более 150 КБ JS **(оценка, цель)**.
- **Функции MVP:** категории, фото, КБЖУ/аллергены, стоп-лист из POS, мультиязычность (RU/EN + KZ/UZ для СНГ), «позвать официанта» и «попросить счёт» (уведомление в Telegram персоналу), чаевые по ссылке (CloudTips / Нетмонет).
- **Фаза 2:** заказ и оплата со стола (ЮKassa / CloudPayments / СБП), отправка заказа в POS.
- **QR:** статичный URL `/{venue}/{table}`. Меню меняется без перепечатки наклеек.

## 3. Хостинг в РФ (152-ФЗ)

С 01.07.2025 действует требование первичной обработки ПДн граждан РФ в базах на территории РФ (ст. 18 ч. 5 152-ФЗ). Поэтому телефоны, имена и записи звонков храним в РФ.

| Провайдер | Что брать | Ориентир, ₽/мес (MVP) |
|---|---|---|
| Yandex Cloud | Managed PostgreSQL, Object Storage, Serverless Containers; рядом SpeechKit и YandexGPT | 8-20 тыс. **(оценка)** |
| Selectel | VPS/Managed DB, S3, CDN; дешевле на «железе» | 5-12 тыс. **(оценка)** |
| Timeweb Cloud | VPS + Managed DB, проще и дешевле для старта | 3-8 тыс. **(оценка)** |
| VK Cloud | альтернатива с S3/K8s | 8-15 тыс. **(оценка)** |

Рекомендация: **Yandex Cloud**, если голос и LLM берём у Яндекса (одна площадка, один договор). Если нет, Selectel или Timeweb. Деплой через Docker Compose, затем при росте k8s. CI: GitHub Actions или GitLab CI; GitVerse как запасной вариант на случай санкционных рисков.

## 4. Интеграции с POS

| POS | API | Возможности | Сложность |
|---|---|---|---|
| **iiko** | iikoCloud API (`https://api-ru.iiko.services`, документация `/docs`), REST, токен по apiLogin | номенклатура, внешние меню, стоп-листы (вебхуки), заказы на доставку и в зал, лояльность iikoCard | средняя; 2-3 нед. **(оценка)** |
| **r_keeper** | Delivery/White Server API, облачный r_keeper; XML-интерфейс к станции у локальных установок | меню, заказы, у части версий нужен дилер/лицензия | высокая; 3-5 нед. **(оценка)** |
| **Poster** | REST API (joinposter), OAuth-приложение, маркетплейс | меню, остатки, заказы, клиенты | низкая; 1-2 нед. **(оценка)** |
| Quick Resto, Saby Presto, Frontpad | REST | меню и заказы | 1-2 нед. каждая **(оценка)** |

Официальная цена доступа к iikoCloud API в открытых источниках не публикуется. apiLogin выдаёт сам ресторан или дилер, условия партнёрства согласуются с iiko. Тарифы самой iiko начинаются от ~2 500 ₽/мес ([toolfox](https://toolfox.ru/services/s/iiko)). Готовые клиенты и документация: [context7 iiko-cloud-api](https://context7.com/salesduck/iiko-cloud-api), [wc-iikocloud](https://it.wordpress.org/plugins/wc-iikocloud/).

**Паттерн:** адаптер `PosAdapter` с методами `syncMenu()`, `getStopList()`, `createOrder()` и нормализованная модель меню. Синхронизация: вебхук плюс полный пересинк по крону раз в 15 мин. На старте делаем **только чтение меню и стоп-листа**, запись заказов вводим в фазе 2.

## 5. Боты: Telegram / VK / MAX

- **Telegram:** grammY (TS) или aiogram 3 (Python); Mini App переиспользует PWA-меню. Бронь, заказ навынос, FAQ через RAG, уведомления персоналу.
- **VK:** VK Bot API (Long Poll / Callback), vk-io. Аудитория 35+ и регионы.
- **MAX** (мессенджер VK, продвигается государством, в 2025-2026 активно растёт): Bot API на dev.max.ru / platform-api, схема близка к Telegram. Обязателен к поддержке как «страховка» на случай ограничений Telegram **(оценка риска)**.
- Архитектура: единый **channel gateway**. Нормализуем входящие сообщения, а диалоговая логика и RAG общие для всех каналов. Новый канал добавляется за 3-5 дней **(оценка)**.

## 6. Голосовой ИИ-администратор (брони, часы работы, меню)

**Пайплайн:** входящий звонок → SIP-транк (Mango Office / Zadarma / Телфин) → медиасервер (Asterisk/FreeSWITCH или Voximplant) → потоковый ASR → LLM + RAG + function calling (`create_booking`, `check_availability`) → TTS → в ответ. Если ИИ не справляется или гость просит, переводим на живого администратора.

- **Телефония:** Zadarma дешевле и даёт SIP, API и вебхуки. У Mango Office есть сильная ВАТС, API и CRM-интеграции, но дороже. Номер плюс минуты: ~500-2 000 ₽/мес на точку **(оценка)**. Самый быстрый путь к MVP: **Voximplant** (готовые коннекторы к ASR/TTS и LLM, оплата поминутная).
- **ASR/TTS:** Yandex SpeechKit (тарифы обновлены 07.07.2026, потоковое распознавание тарифицируется как синхронное: [yandex.cloud/docs/speechkit/pricing](https://yandex.cloud/ru-kz/docs/speechkit/pricing)). SaluteSpeech лучше на шумной речи (WER ~0,26 против ~0,63 по бенчмарку SimbirSoft, пересказ [toolfox](https://toolfox.ru/blog/speechkit-salutespeech-whisper)), **но с 15.07.2026 новым юрлицам недоступны пакеты и pay-as-you-go** ([developers.sber.ru](https://developers.sber.ru/docs/ru/salutespeech/tariffs/legal-tariffs)), то есть подключение только по индивидуальному договору. Вывод: основной провайдер **SpeechKit**, SaluteSpeech держим резервом при наличии договора.
- **Себестоимость минуты разговора** (ASR + TTS + LLM + телефония): ~3-8 ₽ **(оценка)**. Ресторан с ~600 мин/мес тратит ~2-5 тыс. ₽, что ниже стоимости администратора на линии.
- **Латентность:** цель < 1,5 с до начала ответа. Нужны стриминг ASR, короткие промпты и стриминговый TTS **(оценка)**.
- **Юр. часть:** в начале звонка предупреждаем о записи и ИИ; записи храним в РФ.

## 7. RAG по меню и FAQ

- Источники: нормализованное меню из POS, FAQ заведения (часы, парковка, детское меню, банкеты), политика брони.
- Объём маленький (сотни блюд), поэтому **pgvector** в том же Postgres. Отдельная векторная БД не нужна. Эмбеддинги Yandex Embeddings или GigaChat Embeddings; локально multilingual-e5.
- Гибридный поиск: BM25 (pg full-text) плюс вектор, фильтры по `venue_id`, `in_stop_list=false`, аллергенам.
- **Цены и стоп-лист не отдаём из текста эмбеддинга.** LLM получает их tool-вызовом из БД, иначе возможны галлюцинации цен.
- LLM: YandexGPT Lite/Pro или GigaChat (данные в РФ). Расход на заведение ~300-1 500 ₽/мес при типовом трафике **(оценка)**.
- Оценка качества: набор из 50-100 тестовых вопросов на заведение, регрессия при смене промпта.

## 8. Админка

- React + Refine/React-Admin или shadcn/ui. Роли: владелец, менеджер, оператор агентства (наша команда для онбординга).
- Разделы: заведения и столы (генерация PDF с QR), меню (ручное и из POS), стоп-лист, FAQ для RAG, брони, лог диалогов и звонков с прослушкой, аналитика (сканы QR, популярные блюда, конверсия звонков в брони), биллинг.
- Аналитика: события в ClickHouse или просто Postgres плюс Metabase на старте; Яндекс Метрика на PWA.

## 9. Сроки и трудозатраты

Команда: 1 fullstack TS, 1 backend/AI, 0,5 дизайнер, 0,3 PM/QA **(оценка)**.

| Этап | Содержание | Срок | Чел.-дни |
|---|---|---|---|
| 0 | Инфраструктура, мультиарендность, авторизация, CI | 1 нед | 8 |
| 1 | QR-меню PWA плюс админка меню, PDF с QR, вызов официанта | 3-4 нед | 35 |
| 2 | Интеграции iiko и Poster (чтение меню и стоп-листа) | 3 нед | 25 |
| 3 | Telegram плюс MAX/VK боты, channel gateway, RAG FAQ | 3 нед | 25 |
| 4 | Голосовой ИИ (Voximplant/Zadarma + SpeechKit + LLM), брони | 4 нед | 35 |
| 5 | r_keeper, заказ и оплата со стола | 4-5 нед | 35 |
| | **MVP (этапы 0-3)** | **~2,5 мес** | **~95** |
| | **Полный (0-5)** | **~5 мес** | **~165** |

Стоимость разработки при ставке ~3-4,5 тыс. ₽/час: MVP ~2,3-3,4 млн ₽, полный объём ~4-6 млн ₽ **(оценка)**. Бюджетный вариант: QR-меню на no-code/готовом сервисе плюс Telegram-бот на n8n (self-hosted) и Salebot за 2-4 недели и 200-500 тыс. ₽. Подходит для проверки спроса до собственной разработки.

## 11. Риски

1. Блокировки/замедления Telegram, поэтому MAX и VK обязательны.
2. Изменение тарифов вендоров (пример: SaluteSpeech закрыл pay-as-you-go 15.07.2026), поэтому нужна абстракция провайдеров ASR/TTS/LLM.
3. Доступ к API r_keeper зависит от дилеров. Начинать с iiko и Poster.
4. 152-ФЗ: локализация, согласия, уведомление РКН об обработке ПДн.
5. Галлюцинации цен закрываются tool-вызовами к БД и запретом свободных цен в ответах.
