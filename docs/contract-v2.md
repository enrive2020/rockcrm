# Контракт этапа 2 — «Карточка ученика и жизненный цикл абонемента»

Продолжение [этапа 1](contract-v1.md). Правила транспорта, аутентификации,
формата ошибок и часового пояса берутся оттуда без изменений.

---

## Зачем этот этап

После этапа 1 абонемент умеет только уменьшаться. Его нельзя продать,
продлить, заморозить на каникулы и нельзя посмотреть, куда делись занятия.
Это ровно те действия, из-за которых администратор до сих пор держит
параллельную таблицу в Excel, — и ровно то, что не закрыто ни у одного
конкурента.

## Границы этапа

Входит:

- Поиск ученика и его карточка: семья, абонемент, история, заметки
- Журнал движений абонемента, видимый администратору
- Продажа абонемента и продление
- Заморозка и её снятие
- Список отработок с их сроками

Не входит: воронка заявок, кабинет родителя, приём платежей через
провайдера, редактирование расписания, сгорание отработок по расписанию
(ночное задание — следующий этап).

## Что уже есть и переиспользуется

Схема БД содержит всё необходимое, менять её нельзя:
`subscription`, `subscription_entry`, `subscription_hold`, `makeup_credit`,
`subscription_plan`, `payment`, `family`, `family_member`.

Читайте комментарии в `db/003_billing.sql` — там объяснено, почему остаток
считается из журнала, а правила копируются в абонемент при продаже.

На бэкенде уже есть слой доступа, обработка ошибок базы, изоляция тенантов
и модуль правил `app/rules.py`. Новую логику встраивайте в существующую
структуру, а не рядом с ней.

## Ресурсы

### `GET /api/v1/students?query=<строка>&branch_id=<uuid>&limit=20`

Поиск для строки поиска в интерфейсе. Ищет по имени ученика **и по имени
и телефону плательщика**: администратору звонит родитель, а не ребёнок,
и искать он будет по тому, кто на линии.

```json
[{
  "id": "...", "name": "Амина Сагындык", "age": 9,
  "discipline": "Барабаны", "teacher": "Дмитрий Шарапов",
  "branch": "Аль-Фараби 53В",
  "subscription": {"lessons_balance": 5, "lessons_total": 8,
                   "valid_until": "2026-08-31", "status": "active"},
  "payer": {"name": "Гульнара Сагындык", "phone": "+77015550003"}
}]
```

`subscription` — действующий абонемент или `null`.

### `GET /api/v1/students/{id}`

Карточка. Визуальный ориентир — экран «Ученик» в `prototype/index.html`.

```json
{
  "id": "...", "name": "Амина Сагындык", "age": 9,
  "discipline": "Барабаны", "teacher": "Дмитрий Шарапов",
  "branch": "Аль-Фараби 53В", "started_on": "2026-02-04",
  "status": "active",

  "family": {
    "id": "...",
    "payer": {"name": "Гульнара Сагындык", "phone": "+77015550003"},
    "discount_pct": 10,
    "members": [
      {"student_id": "...", "name": "Амина", "age": 9,
       "discipline": "Барабаны", "lessons_balance": 5},
      {"student_id": "...", "name": "Тимур", "age": 12,
       "discipline": "Гитара", "lessons_balance": 3}
    ],
    "paid_this_month": 97200,
    "debt": 0
  },

  "subscription": {
    "id": "...", "plan_name": "Барабаны, 2 раза в неделю, 55 мин",
    "lessons_total": 8, "lessons_balance": 5, "makeups_balance": 1,
    "price": 54000, "lesson_price": 6750,
    "valid_from": "2026-08-01", "valid_until": "2026-08-31",
    "status": "active",
    "rules": {"no_show_burns": true, "cancel_notice_hours": 24,
              "cancel_early_effect": "makeup",
              "teacher_cancel_effect": "makeup",
              "makeup_ttl_days": 30, "freeze_days_per_year": 14},
    "holds": [{"id": "...", "from": "2026-08-14", "to": "2026-08-25",
               "days": 11, "reason": "каникулы"}],
    "freeze_days_used": 11,
    "freeze_days_left": 3
  },

  "makeups": [
    {"id": "...", "granted_for": "2026-08-02", "expires_on": "2026-09-01",
     "days_left": 20, "used_at": null}
  ],

  "ledger": [
    {"id": 42, "date": "2026-08-07", "kind": "charge",
     "title": "Занятие проведено", "teacher": "Шарапов",
     "lessons_delta": -1, "makeups_delta": 0, "amount": null}
  ],

  "notes": [
    {"date": "2026-08-07", "author": "Дмитрий Шарапов",
     "body": "...", "homework": "...", "tags": ["..."]}
  ],

  "churn_risk": {"level": "medium", "score": 46,
                 "reasons": ["1 прогул за 30 дней",
                             "абонемент кончается через 2 занятия"]}
}
```

Требования:

- `ledger` — прямое отражение `subscription_entry`, **новые сверху**.
  `title` — человеческая формулировка вида «Занятие проведено»,
  «Прогул без предупреждения», «Оплата абонемента». Это тот самый экран,
  которым администратор отвечает на «куда делось занятие».
- `freeze_days_used` считается за календарный год, `freeze_days_left` —
  остаток от лимита из правил абонемента.
- `churn_risk` — простая эвристика на прогулах, остатке и стаже.
  Формулу выбирайте сами, но каждая причина в `reasons` обязана быть
  проверяемым фактом, а не оценкой.

### `GET /api/v1/plans?discipline_id=&format=`

Тарифы для формы продажи.

```json
[{"id": "...", "name": "Барабаны, 2 раза в неделю, 55 мин",
  "discipline": "Барабаны", "format": "individual",
  "duration_min": 55, "lessons_count": 8, "valid_days": 31,
  "price": 54000}]
```

### `POST /api/v1/students/{id}/subscriptions`

Продажа абонемента или продление — это одна операция: продление есть
продажа следующего абонемента.

```json
{
  "plan_id": "...",
  "starts_on": "2026-09-01",
  "discount_pct": 10,
  "promo_code": "RS25",
  "payment": {"amount": 48600, "method": "kaspi"},
  "carry_over": true
}
```

- `payment` необязателен: абонемент можно оформить с долгом, деньги
  донесут позже. Тогда в карточке появляется `debt`.
- `carry_over` переносит неиспользованный остаток предыдущего абонемента,
  если правила школы это позволяют (`rules.carry_over_lessons`). По умолчанию
  правило равно нулю — перенос не делается, и это надо явно показать в ответе.
- Правила копируются в новый абонемент **из настроек школы на момент
  продажи**, а не из предыдущего абонемента: старый жил по условиям своей
  покупки, новый живёт по текущим.

Ответ `201`:

```json
{
  "subscription_id": "...",
  "lessons_total": 8, "lessons_balance": 8,
  "valid_from": "2026-09-01", "valid_until": "2026-10-01",
  "price": 54000, "discount_pct": 10, "charged": 48600,
  "carried_over": 0,
  "payment_id": "...",
  "debt": 0
}
```

Ошибки: `422`, если у ученика уже есть действующий абонемент на тот же
период и школа это запрещает; `404`, если тариф из другого тенанта.

### `POST /api/v1/subscriptions/{id}/holds`

```json
{"from": "2026-08-14", "to": "2026-08-25", "reason": "каникулы"}
```

Заморозка сдвигает `valid_until` на число замороженных дней. Занятия,
попавшие в интервал, отменяются без списания.

Ответ `201` — что именно изменилось:

```json
{"hold_id": "...", "days": 11,
 "valid_until_before": "2026-08-31", "valid_until_after": "2026-09-11",
 "lessons_cancelled": 3,
 "freeze_days_left": 3}
```

Ошибки:

- `409`, если интервал пересекается с существующей заморозкой. База
  это запрещает ограничением исключения — переведите его в понятный текст.
- `422`, если превышен годовой лимит дней из правил абонемента; в тексте
  укажите, сколько дней осталось.
- `422`, если заморозка начинается в прошлом.

### `DELETE /api/v1/subscriptions/{id}/holds/{hold_id}`

Снятие заморозки возвращает `valid_until` назад. Отменённые занятия
**не восстанавливаются** — их слоты уже могли занять; в ответе честно
сообщите, сколько занятий было отменено и что их нужно поставить заново.

## Требования к бэкенду

- Продажа абонемента — одна транзакция: `subscription`, запись `purchase`
  в журнал, платёж, аудит. Абонемент без записи в журнале означал бы
  остаток, взявшийся ниоткуда.
- Заморозка — тоже одна транзакция: `subscription_hold`, сдвиг
  `valid_until`, отмена занятий, аудит.
- Остаток нигде не вычисляется вручную: он приходит из кэша, который
  ведёт триггер. Если понадобилось посчитать его в коде — значит, схема
  используется неправильно.
- Тесты: продажа наполняет журнал; продление не трогает старый абонемент;
  заморозка сдвигает срок ровно на число дней и отменяет занятия внутри
  интервала; пересечение заморозок отвергается; годовой лимит соблюдается;
  снятие заморозки возвращает срок назад; чужой тенант получает 404.
- Демо-данные дополните так, чтобы карточка Амины Сагындык выглядела
  как в прототипе: семья с двумя детьми, скидка, история, заметки.

## Требования к фронтенду

- Экран «Ученики»: строка поиска и список результатов.
- Карточка ученика по мотивам прототипа: семья с плательщиком, абонемент
  сегментированным счётчиком, правила списком, движение по абонементу
  таблицей, заметки к урокам, риск оттока.
- Диалог продажи: выбор тарифа, дата начала, скидка и промокод, способ
  оплаты, **предпросмотр итога до подтверждения** — сколько занятий,
  до какого числа, сколько к оплате. Тот же принцип, что с отметкой:
  администратор видит результат прежде, чем нажать.
- Диалог заморозки: интервал, причина, показ оставшегося лимита дней
  и предупреждение, сколько занятий будет отменено.
- Из расписания клик по имени ученика ведёт в его карточку.
- Состояния загрузки, пустого результата поиска и ошибки обязательны.
