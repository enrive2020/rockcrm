# Тесты схемы

Проверяют не то, что таблицы создались, а то, что база **не даёт** сделать
неправильное: занять кабинет дважды, списать одно занятие двумя записями,
переписать журнал, увидеть чужого тенанта.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
python tests/test_schema.py
```

Скрипт поднимает собственный кластер PostgreSQL в `tests/pgdata`, применяет
все миграции из `db/` и прогоняет проверки. Существующая база не нужна
и не затрагивается.

## Важное ограничение

`pgserver` поставляет урезанную сборку PostgreSQL **без `btree_gist`**.
Без этого расширения не создаются ограничения исключения, запрещающие
двойную бронь кабинета и преподавателя — соответствующие проверки
помечаются `[SKIP]`, а не молча проходят.

Чтобы прогнать их по-настоящему, нужен полноценный PostgreSQL:

```bash
docker run -d --name rockcrm-pg \
  -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=rockcrm \
  -p 5432:5432 postgres:17-alpine
```

Тогда запустите скрипт против него, заменив создание сервера на подключение
по `DATABASE_URL`. Пока `[SKIP]` держится в выводе, главные гарантии
расписания считаются непроверенными.

## Что проверяется

**Расписание** — кабинет нельзя занять дважды; преподаватель не ведёт два
занятия сразу; занятие впритык конфликтом не является; осознанный овербукинг
проходит; отменённое занятие освобождает слот.

**Абонемент** — покупка наполняет, списание уменьшает, отработки живут
отдельно от занятий, нулевой остаток переводит в `exhausted`, пустая запись
журнала отвергается, повторное списание по одной отметке невозможно,
заморозки не пересекаются.

**Целостность** — отказ по заявке требует причины, телефон приводится
к E.164, занятие обязано иметь адресата, `uuid_v7` даёт седьмую версию
и возрастает во времени.

**Изоляция** — тенанты видят только своё; без выставленного `app.tenant_id`
не видно ничего; нельзя записать строку в чужой тенант; журнал абонемента
защищён от правок и удалений; связующие таблицы изолированы через родителя.
